# 시험: superpowers와 ECC를 같이 켜면 손해일까? (2026-10-17)

## 무엇이 궁금했나요
superpowers와 ECC는 둘 다 "개발을 진행하는 순서"를 정해 주는 도구예요.
**둘을 같이 켜면 정말 손해인지, 손해라면 얼마나인지** 직접 돌려 보고 싶었어요.

## 무엇을 해 봤나요
1. **처음 읽는 양 재기** — 도구를 하나도 안 켤 때, 하나만 켤 때, 둘 다 켤 때 Claude Code가 첫 대답에서 읽는 글자 양(토큰)을 쟀어요. 같은 조건으로 두 번 재서 값이 같은지도 봤어요.
2. **같은 일 27번 시키기** — 과제 3개(함수 새로 만들기, 버그 고치기, 코드 정리 후 저장)를 superpowers만 / ECC만 / 둘 다 켠 상태에서 3번씩 시켰어요. 끝난 뒤에는 테스트를 따로 다시 돌려 정말 됐는지 확인했어요.

## 결과는 이랬어요
- **결과물은 똑같았어요.** 27번 모두 성공했어요.
- **하지만 비용은 달랐어요.** superpowers를 쓰는 중에 ECC를 더하면, 같은 일을 하는데
  토큰은 약 **1.9배**, 시간은 약 **1.5배** 더 들었어요.
- **겹치는 기능은 한쪽만 쓰였어요.** 둘 다 켰을 때 ECC의 테스트·디버깅 스킬은 **한 번도** 쓰이지 않았어요. 안 쓰이면서 자리(토큰)만 차지한 거예요.
- **처음 읽는 양:** 도구 없음 23,161 → superpowers +1,377 / ECC +8,198 / 둘 다 +9,238 토큰 (두 번 재도 차이 2토큰 이하).
- **ECC 혼자만의 특징도 발견했어요.** ECC를 켜면 첫 파일 쓰기·명령 실행을 "먼저 사실을 정리하라"며 막는 장치가 매번 작동했어요. 둘이 부딪혀서 생긴 게 아니라 ECC를 켜면 항상 생겨요.

**그래서** 우리 서비스에서 "겹침"은 이렇게 설명할 수 있어요.
> 비슷한 일을 하는 도구를 같이 켜 두면, **안 쓰는 쪽도 매번 읽혀서** 같은 결과에 비용이 더 들어요.

## 주의할 점
- 작은 과제 3개, 3번씩, 모델 하나(sonnet)로만 해 봤어요. 큰 프로젝트에서는 다를 수 있어요.
- "같이 쓰면 결과가 나빠진다"는 이번 시험에서는 **보이지 않았어요.** 그렇게 말하면 안 돼요.
- 우리가 본 ECC는 2.2.0이에요(지금 최신은 2.2.3).
