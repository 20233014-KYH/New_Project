# 시험 7: superpowers × caveman 같이 켜기, 최신판으로 다시 (2026-11-21)

## 왜 다시 했나
10/18 시험(caveman 4.0.1)에서 caveman을 superpowers와 같이 켜고 버그를 고치게 했더니 superpowers의 디버깅 절차를 **3번 중 3번 건너뛰었어요**.
"어려운 버그에서도 괜찮은지"는 확인하지 못했고, 그 사이 두 도구 모두 새 버전이 나왔어요(이슈 #23 "caveman × superpowers 같이 켜는 시험").

## 어떻게
- 과제: 구독 청구 계산 저장소(`fixture/`)에 고객 신고 2건. 증상은 청구서에 보이고, 원인은 `cycle.py`(말일 가입자 날짜가 다음 달로 넘어감)와 `discount.py`(단계마다 내림 안 함·반올림) 두 군데예요.
- 채점: 숨은 테스트 12개(`hidden/`) — 말일·윤년·연말, 단계별 내림, 일할 계산까지. 모델이 새로 쓴 테스트는 세지 않았어요.
- 조건: superpowers 7.0.2만 / superpowers 7.0.2 + caveman 4.1.0, **3번씩**. `--plugin-dir`로 이 실행에만 불러오고, 깨끗한 설정(플러그인 거의 없는 시험용 설정 폴더)·sonnet으로 돌렸어요.
- 시험이 끝난 뒤 caveman이 시험용 설정 폴더에 만든 파일(`.caveman-*`, 상태줄 스크립트)을 지웠어요. 실제 설정은 건드리지 않았어요.

## 결과
| | 숨은 테스트 | 디버깅 절차 불렀나 | 전체 토큰(평균) | 출력 토큰 | 시간 |
|---|---|---|---:|---:|---:|
| superpowers만 | 12·12·12 | 3번 모두 | 285,739 | 2,929 | 30초 |
| + caveman | 12·12·12 | **3번 모두** | 225,987 (**-21%**) | 2,401 (-18%) | 25초 (-17%) |

(가격 가중치 입력 1·캐시 쓰기 1.25·캐시 읽기 0.1·출력 5로 계산하면 66,603 → 61,614, -7%)

- **최신판에선 caveman이 디버깅 절차를 건너뛰지 않았어요.** 결과도 같고, 토큰·시간은 조금 줄었어요.
- 10/18 결과와 다른 이유는 확인하지 않았어요. 버전(caveman 4.0.1→4.1.0, superpowers 6.x→7.0.2)과 과제·켜 둔 플러그인 구성이 모두 달라요.

## 한계
- 버그가 **30초 안에 풀릴 만큼 쉬웠어요.** "어려운 버그"를 만들려 했지만 두 조건 모두 금방 풀었어요. 정말 오래 걸리는 버그에서는 아직 모르겠어요.
- 3번씩이라 토큰 차이(-21%)는 흔들릴 수 있어요.
