# 시험 2: 상태줄 쌍 충돌 + 토큰 절약 도구 효율 (2026-10-17~18)

## 무엇이 궁금했나요
1. **상태줄 쌍** (claude-hud × ccstatusline): 같이 쓰면 진짜로 고장 나는지
2. **토큰 절약 쌍** (caveman × rtk): 도구 하나씩 잰 값을 더하면, 같이 켰을 때 값을 맞힐 수 있는지
3. **추천이 의미 있는지**: 지금 쓰는 조합(superpowers + karpathy + impeccable)에 이 도구를 **더하면** 정말 아껴지는지

## 무엇을 해 봤나요
- **상태줄**
  - 두 도구를 샘플 입력으로 직접 돌렸어요.
  - 설치·삭제 코드에서 상태줄 설정을 어떻게 다루는지 읽었어요.
  - caveman의 상태줄 안내는 가짜 설정 폴더(상태줄 없음 / 있음)로 확인했어요.
- **처음 읽는 양**: 조건 8개 × 2번 = 16번 재 봤어요.
- **같은 일 시키기**: 과제 3개 × 조건 4개(기준 / +caveman / +rtk / +둘 다) × 3번 = **36번** 시켰어요.
  - 끝난 뒤 테스트를 따로 다시 돌려 정말 됐는지 확인했어요.
  - 중간에 구독 사용 한도에 걸려 14번이 실패했어요. 그 기록은 버리고 한도가 풀린 뒤 다시 돌렸어요.
- 도구는 실험 폴더에만 받았어요. 사용자 설정은 바꾸지 않았고, 끝난 뒤 도구가 만든 파일을 지웠어요.

## 결과 1: 상태줄 쌍은 고장이 아니라 "자리 다툼"이에요
- 혼자 돌리면 둘 다 정상이에요.
- 상태줄 자리는 설정에 **딱 하나**라서, 같이 쓰면 **둘 중 하나는 반드시 안 보여요.**
- 나중에 설치하는 쪽이 "이미 상태줄이 있는데 바꿀까요?"라고 **물은 뒤에** 바꿔요. 몰래 덮어쓰지는 않아요.
  - ccstatusline은 바꾸기 전에 원래 설정을 백업해요.
- caveman에도 상태줄 배지가 있어요.
  - 상태줄이 비어 있으면 처음 한 번 "설정하라"는 안내를 넣어요(+126토큰).
  - 이미 다른 상태줄이 있으면 조용히 물러나요. 그래서 caveman 배지는 안 보여요.

→ 판정: **겹침**(같은 자리를 차지해요). 고장은 아니에요.

## 결과 2: 하나씩 잰 값을 더하면 거의 맞아요 (조금 크게 나와요)
같은 조건을 두 번 재 보니 차이는 4토큰 이하였어요.

| 조건 | 첫 응답 입력 토큰 | 도구 없음 대비 |
|---|---:|---:|
| 도구 없음 | 23,167 | — |
| rtk | 23,170 | +3 |
| caveman | 25,690 | +2,523 |
| caveman + rtk | 25,690 | +2,523 (합과 같아요) |
| 기준 조합 | 25,050 | +1,883 |
| 기준 + caveman | 26,852 | +3,685 (합 +4,406보다 약 720 적어요) |

- rtk는 미리 읽히는 양이 **거의 0**이에요. 명령 출력만 줄이는 도구라서예요.
- 스킬이 많아지면 합이 실제보다 조금 커요. 시험 1(superpowers + ECC)에서도 같았어요.
- 그래서 화면에는 **"하나씩 잰 값의 합 = 같이 켰을 때의 최대치"**로 보여 주면 정직해요.

## 결과 3: 더하기 추천의 근거가 처음 생겼어요
36번 모두 성공했어요. 조건마다 9/9예요.

| 기준 대비 | 입력 토큰 | 출력 토큰 | 시간 |
|---|---:|---:|---:|
| + caveman | **-14%** | **-38%** | **-27%** |
| + rtk | -4% | -7% | +2% |
| + 둘 다 | -15% | -34% | -20% |

**caveman은 확실히 아껴요. 다만 함께 알려야 할 점이 두 가지 있어요.**
- **버그 고치기**: superpowers의 디버깅 스킬을 **3번 중 한 번도 안 불렀어요.** 기준 조합은 3번 다 불렀어요.
  - 아낀 양의 일부는 "말이 짧아져서"가 아니라 **"다른 도구의 절차를 건너뛰어서"**예요.
  - 이번에는 결과가 같았지만, 어려운 버그에서도 괜찮을지는 **확인 안 됐어요.**
- **함수 새로 만들기**: 입력이 오히려 **+6%** 늘었어요. 매번 미리 읽히는 약 2,500토큰이 아낀 양보다 컸어요.
- caveman 4.0.1은 말 줄이기 말고도 **스킬 22개**를 함께 넣어요.
  - investigate-first, safe-refactor, surgical-patch, verify-and-stop 같은 스킬은 superpowers·karpathy와 **겹칠 수 있는 후보**예요.
  - 36번 동안 한 번도 쓰이지 않았어요.

**rtk는 작은 과제에서는 효과가 거의 없어요.**
- rtk가 바꾼 명령의 출력은 **69%** 줄었어요(명령 19개에서 1.7K토큰).
- 하지만 한 번 실행에 약 100토큰 수준이에요. 전체(약 17만)에서는 실행마다 생기는 차이와 구분이 안 돼요.
- Windows에서 Claude가 테스트를 **PowerShell로 돌리면** rtk가 끼어들지 못해요. rtk는 Bash만 가로채요.

**caveman과 rtk는 서로 부딪히지 않아요.**
- 훅 오류가 0번이었어요.
- 줄이는 곳이 서로 달라요(말 / 명령 출력).
- → 판정: **보완**.

## 그래서 서비스에는 이렇게 쓸 수 있어요
- **빼기 추천**: 근거가 확실해요(시험 1). 예: "superpowers를 쓰면 ECC는 꺼도 결과가 같고 비용은 줄어요."
- **더하기 추천**: 근거가 생겼지만 **조건이 붙어요.**
  - 예: "caveman을 더하면 출력 -38%. 단, 버그 고칠 때 디버깅 절차를 건너뛸 수 있어요."
  - 예: "rtk는 출력이 큰 명령에서만 효과가 있어요. Windows PowerShell에서는 작동하지 않아요."
  - 그래서 사용자에게 **무슨 일을 주로 하는지, 어떤 환경인지** 묻는 단계를 기획에 넣어야 해요.
- **상태줄 도구끼리**: "하나만 고르세요."

## 주의할 점
- 작은 과제 3개를 3번씩, 모델 하나(sonnet)로만 해 봤어요.
- caveman이 디버깅 스킬을 건너뛴 **이유는 추정**이에요. 3번 중 3번 그랬다는 것만 사실이에요.
- 해 본 버전: claude-hud 0.11.3, ccstatusline 2.2.32, caveman 4.0.1, rtk 1.0.1, Claude Code 2.1.191

## 파일
| 파일 | 내용 |
|---|---|
| `results_36runs.csv` | 36번 각각의 기록(토큰, 시간, 쓰인 스킬, Bash/PowerShell 횟수, rtk가 바꾼 명령 수, 성공 여부) |

**다시 돌려 보려면**
1. `code/`의 파일을 시험 1 폴더의 `code/`(`run_experiment.py`가 있는 곳)에 함께 둬요.
2. 그 옆에 `tools_sandbox/`를 만들고, 그 안에 아래 세 가지를 넣어요.
   - caveman 저장소(git clone)
   - `bin/rtk.exe`, `bin/jq.exe`
   - `hooks/rtk-rewrite.sh`(rtk 저장소의 `hooks/claude/` 안에 있어요)
3. 아래 두 명령을 차례로 돌려요.

```
python run_tools_exp.py ctx      # 처음 읽는 양
python run_tools_exp.py task 3   # 36번 시키기
```

rtk는 `rtk init -g`를 쓰지 않고, 이 시험 세션의 설정에만 훅으로 걸었어요(전역 설정이 바뀌지 않게).
