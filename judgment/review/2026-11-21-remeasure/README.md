# 처음 읽는 양 다시 재기 + 겹침 기준 바꾸기 (2026-11-21)

## 왜 다시 쟀나요
- 카탈로그 최신화(`data/update/refresh.py`)에서 36개 중 26개가 우리가 잰 뒤 새 버전이 나왔다고 나왔어요.
- 그래서 추천에 자주 나오는 4개(superpowers, caveman, pm-skills, planning-with-files)를 먼저 최신판으로 다시 쟀어요.

## 4개를 먼저 재 보니 (`versions4.csv`)
- **도구 버전 차이는 작았어요.** 옛 버전과 최신판을 같은 날 같은 조건에서 재면 값이 거의 같아요. pm-skills만 스킬·명령이 3개씩 늘었어요(2.2.0 → 2.3.0).
- **대신 화면에 있던 숫자가 지금과 달랐어요.** 같은 옛 버전인데도 10/18 값과 크게 달라요(예: pm-skills 1,280 → 7,870).
  - 원인은 도구가 아니라 Claude Code 버전 변화(2.1.191 → 2.1.318)로 보여요.
  - Claude Code가 스킬 목록을 읽어 들이는 방식이 바뀐 것 같다는 추정만 하고, **확인은 안 했어요.**
- 그래서 36개 전부를 지금 Claude Code로 다시 쟀어요.

## 36개 다시 잰 방법 (`measured.csv`)
- 10/18과 같은 환경(같은 저장소 버전, 같은 실행 방법)에서 Claude Code만 지금 버전으로 바꿔 쟀어요. 실행 파일은 `code/measure36_rerun1121.py`예요(결과 폴더만 다른 10/18 measure36.py).
  - 그래서 카탈로그의 "잰 버전"은 그대로이고, 숫자만 지금 Claude Code 기준이에요.
- 도구 없는 빈 세션: **32,849토큰**(10/18은 19,138). 처음과 끝에 2번씩 쟀고, 차이는 몇 토큰이에요.
- 1·2회차 차이는 대부분 5토큰 이하예요.
- **이상한 값**: tdd-guard는 켜니 오히려 468토큰 줄었어요. 원인을 확인하지 않아서 카탈로그에는 0으로 두고 메모를 달았어요.
- 측정 비용: haiku에게 "ok" 한 마디만 물어서 아주 적어요.

## 겹침 기준을 바꿨어요 (형원 확정)
- **기준값 = 빈 세션 처음 읽는 양의 5%** → 지금 **1,642토큰**.
  - 처음 기준 1,000도 당시 빈 세션의 약 5%였어요. Claude Code가 또 바뀌면 빈 세션만 다시 재면 돼요.
- **둘씩 볼 때**: 같은 일을 하는 두 도구에서 작은 쪽이 기준 이상이면 겹침이에요. 어느 쪽을 꺼도 그만큼은 아낀다는 뜻이에요.
  - 예전 규칙 "둘 다 1,000 이상"과 계산은 같고 기준값만 바뀌었어요.
- **여러 개 같이 쓸 때(새로 추가)**: 도구함에 서로 모두 같은 일을 하는 도구가 3개 이상 있으면 합쳐서 봐요.
  - 가장 큰 것을 남겨도 아끼는 양(합 - 최댓값)이 기준 이상이면 하나만 남기라고 추천해요.
  - 남길 도구는 지금은 처음 읽는 양이 가장 작은 것이에요(빼기의 임시 규칙과 같음).
- 적용 스크립트: `data/update/apply_criteria.py`
