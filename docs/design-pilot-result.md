# 디자인 판정 파일럿 결과 (2026-10-16)

목적: "도구 설명서에서 겨냥 축을 뽑고(B) + 공개 기준·자동 측정으로 재는(A)" 방법이 실제로 되는지 확인.
이 파일럿은 **도구가 좋은지 나쁜지의 증거가 아니라 측정 방법의 시험**이다.

## 설계
- 과제 2개: 로그인 화면(login), 서점 관리자 대시보드(dash)
- 조건 3개: 도구 없음(none) / frontend-design 설명서(fd) / impeccable 설명서 + craft-floor(imp)
- 조건당 과제별 2회 = 조건당 4쪽, 총 12쪽
- 생성 모델: 무료 라우터의 gpt-oss-120b 고정(조건 사이 모델 동일), temperature 0.7
- 측정: Playwright(Chrome)로 1280px·375px에서 실제로 그려 DOM/CSS를 읽음 (`prototype/design_pilot/measure_pages.py`)
- 한계: 설명서 글을 시스템 지시문으로 준 것이며 실제 Claude Code 플러그인(스크립트·훅·대화 단계) 실행이 아님

## 결과 (조건별 평균, 4쪽)
| 항목 | none | fd | imp | 읽는 법 |
|---|---:|---:|---:|---|
| 간격 값 중 4px 배수 비율(%) | 41.5 | 51.8 | **90.2** | imp는 4쪽 모두 77~100, none은 4쪽 모두 58 이하 → **뚜렷** |
| 이모지를 아이콘으로 쓴 곳 | **7** | 0 | 0 | 도구를 쓰면 사라짐 (impeccable은 명시적으로 금지) |
| focus 스타일이 있는 쪽 | 2/4 | 2/4 | **4/4** | impeccable의 states 기준과 일치 |
| 모션 감소 대응이 있는 쪽 | 0/4 | **2/4** | 0/4 | frontend-design 설명서의 "reduced motion respected"와 일치 |
| 글꼴 종류 | 1.2 | **2.2** | 1.8 | frontend-design의 "서체를 의도적으로 고르라"와 방향 일치 |
| 글자 대비 실패 수 | 4.8 | 4.2 | 2.8 | 과제 차이가 더 커서(login 0~3, dash 5~10) **불분명** |
| 최저 대비 비율 | 3.5 | **2.5** | 3.8 | fd가 가장 낮음 → 개성 추구와 접근성 하한이 부딪힐 수 있음 |
| 모바일 가로 넘침 | 1/4 | 1/4 | 1/4 | 차이 없음 |
| 금지 패턴(eyebrow, 섹션 번호, 그라데이션 글자, 하드 그림자, → 글자) | 0 | 0 | 0 | 기본 모델이 이미 안 함 → 구별 못 함(바닥 효과) |
| 같은 모양 카드 3개 이상 | 1 | 1 | 2 | 과제(요약 숫자 3개 요구)가 원인이라 **측정이 흐려짐** |

## 타당성 확인 (화면을 직접 본 결과, login 3종)
- imp: 간격이 고르고 여백이 정돈됨 → 4px 비율 91%와 일치
- fd: 남색 배경과 세리프 제목으로 **가장 개성 있음**, 다만 라벨과 입력창이 붙고 버튼이 작아 답답함 → 4px 비율 53%, 대비 실패와 일치
- 즉 측정 항목은 **정돈됨(일관성·접근성 하한)** 을 잘 잡았고, **개성·미적 매력**은 잡지 못함

## 결론
1. 흐름(설명서 읽기 → 겨냥 축 정리 → 생성 → 렌더 → 자동 측정 → 조건 비교)은 **무료 도구만으로 끝까지 동작**한다.
2. **자동 측정이 구별해 준 축**: 간격 격자, 이모지 아이콘, 상태 스타일(focus), 글꼴 수, 모션 감소 대응.
3. **구별 못 한 축**: 대비(과제 영향이 더 큼), 금지 패턴(바닥 효과), 카드 반복(과제 요구에 가려짐).
4. **도구가 겨냥한 축과 측정되는 축이 다를 수 있다.** frontend-design은 "개성"이 목표인데 측정은 "일관성"이 쉽다. 카드에 두 가지를 따로 표시해야 한다.
5. 표본이 작다(조건당 4쪽, 모델 1개). 방향 확인용이며 수치를 결론으로 쓸 수 없다.
