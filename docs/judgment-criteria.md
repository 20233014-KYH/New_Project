# 판정 기준 초안 v0.1 (팀 검토용)

작성: 2026-10-16 · 상태: 초안, 팀 합의 전
이 문서는 제안서 v4의 "AI 판정"이 **무엇을, 어떤 근거로, 어떻게 표시할지**를 정합니다.

---

## 1. 판정이 알려 주는 것 (4종)

| 질문 | 답의 형태 | 근거를 댈 수 있나 |
|---|---|---|
| 같이 써도 되나 | 겹침 / 용도별 / 보완 / 관련 없음 (+ 재현된 문제가 있을 때만 '동작 문제 확인됨') | 일부는 계산·실측, 나머지는 AI 해석 |
| 언제 추천하나 | 상황별 이유 한 줄 | AI 해석 (카탈로그 안에서만) |
| 어떤 효과가 있나 | 토큰 방향, 바뀌는 영역 | 토큰은 계산, 품질은 3장 방식 |
| 이 도구는 어디까지 할 수 있나 | **역할 범위** | 계산 (코드가 구성 요소를 셈) |

## 2. "위험도" 대신 "역할 범위"로 표시 (결정 반영)

"안전/위험"으로 단정하지 않고 **이 도구가 어디까지 손댈 수 있는지**를 보여 줍니다.

표시할 항목 (모두 코드가 계산하는 사실):
- 구성 요소 개수: 스킬 / 에이전트 / 명령 / MCP 서버
- 훅: 전체 개수와 **실행되는 시점별 개수**(세션 시작, 도구 사용 전·후, 응답 종료 등). '모든 도구 호출에 걸리는지'는 시점별로 나눠 센 뒤에만 쓴다
- 상시 토큰 추정(글자수÷3)

문구 예시:
> 이 도구는 훅 22개가 7가지 시점에 실행됩니다(도구 사용 전 8개, 응답 종료 7개 등). 설치하기 전에 범위를 확인하세요.

규칙:
1. "안전", "위험", "문제없음" 같은 단정 표현을 쓰지 않는다.
2. 카드마다 "도움말이며 보증이 아닙니다" 한 줄을 고정한다.
3. 패턴 검사(네트워크 호출, 민감 경로 등)는 오탐이 많아서 **화면에 쓰지 않고** 검수자의 참고용으로만 쓴다. (ECC 점검에서 주석·보호 코드가 대부분 걸렸음)
4. 우리가 확인하지 못한 항목은 "확인 안 됨"으로 표시한다. 없다는 뜻이 아니다.

## 3. 애매한 "품질" 판정은 이렇게 정한다 (초안, 합의 필요)

원칙: **"품질이 좋아진다"고 쓰지 않는다.** 무엇이 달라지는지를 **관찰할 수 있는 항목**으로 쪼개고, 근거 수준을 같이 표시한다.

### 3-1. 근거 수준 3단계 (모든 판정 항목에 붙임)
| 수준 | 뜻 | 화면 표시 |
|---|---|---|
| 계산 | 코드가 센 값 (토큰, 훅 개수, 구성 요소) | 사실 |
| 문서 근거 | 도구 문서가 주장하는 효과를 출처와 함께 인용 | "제작자 주장" |
| 직접 확인 | 우리가 같은 과제를 돌려 비교한 기록이 있음 | "직접 확인 (날짜, 모델, 과제 수)" |

AI가 문서만 읽고 쓴 추정은 "AI 추정"이라고 따로 표시하고, 위 3단계 중 어디에도 올리지 않는다.

### 3-2. 설명서에서 "겨냥한 축"을 뽑고, 공개 기준으로 "측정한 축"을 만든다 (파일럿으로 확인됨)
두 가지를 **따로** 보여 줍니다.
- **겨냥한 축(제작자 주장)**: 도구 설명서(예: impeccable의 `craft-floor.md`, frontend-design의 `SKILL.md`)가 스스로 적은 목표와 금지 목록. 근거 종류는 `doc`.
- **측정한 축(우리가 잰 것)**: 결과물을 실제로 그려서 자동으로 센 값. 근거 종류는 `tested`.

**자동으로 잴 수 있는 항목** (스크립트 `prototype/design_pilot/measure_pages.py`로 확인함)
| 항목 | 기준 | 파일럿에서 구별됐나 |
|---|---|---|
| 간격이 4px 배수인 비율 | 일관성 | **예** (도구 없음 42%, impeccable 90%) |
| 이모지를 아이콘으로 씀 | impeccable 금지 항목 | **예** (7곳 → 0곳) |
| 키보드 포커스 스타일 | impeccable states, WCAG | 예 (2/4쪽 → 4/4쪽) |
| 모션 감소 대응 | frontend-design 품질 하한 | 예 (0/4쪽 → 2/4쪽) |
| 글꼴·글자 크기 종류 수 | 서체 체계 | 일부 (fd는 글꼴이 늘어남) |
| 글자 대비 비율 | WCAG 4.5:1 / 3:1 | 불분명 (과제 영향이 더 큼) |
| 모바일(375px) 가로 넘침, 터치 영역 | 반응형 기본 | 아니오 (차이 없음) |
| 입력창 이름(label), 이미지 alt, lang, main | 기본 접근성 | 차이 작음 |
| 금지 패턴(eyebrow, 섹션 번호, 그라데이션 글자, 하드 그림자 등) | impeccable Refuse 목록 | 아니오 (이미 안 함, 바닥 효과) |

**자동으로 못 재서 사람이 보는 항목**: 정보의 위계, 목적에 맞는지, 개성(독특함). 두 사람이 따로 채점하고, 같은 크기의 결과를 익명으로 비교합니다. 기준 디자인 2~3개는 "정답"이 아니라 **눈높이를 맞추는 예시**로만 보여 줍니다.

**주의**: 도구가 겨냥하는 것과 측정되는 것이 다를 수 있습니다. 파일럿에서 frontend-design은 "개성"을 겨냥해 가장 독특한 화면을 냈지만 간격 일관성과 최저 대비가 낮았습니다. 측정값만 보여 주면 이 도구가 나쁘게 보이므로 겨냥한 축을 함께 표시합니다.

### 3-3. 직접 확인하는 방법 (대표 도구만)
1. 같은 과제 3개 이상을 준비한다 (예: 로그인 화면, 대시보드, 폼 검증)
2. **도구 없이 / 도구 있이** 같은 모델·같은 지시로 각각 **10쪽 이상** 만든다 (파일럿은 조건당 4쪽이라 부족했음)
3. 결과물을 실제로 그려서 자동 측정하고, 스크린샷과 코드를 저장한다
4. **같은 과제 안에서만 조건을 비교한다** (과제 영향이 조건 영향보다 큰 항목이 있음)
5. 사람이 보는 항목은 두 사람이 따로 채점하고, 다르면 합의한다
6. 기록: 날짜, 모델 이름과 버전, 과제, 도구 버전, 항목별 결과

화면에는 이렇게 보입니다.
> 간격 일관성 · 직접 확인(2026-10, 과제 3개, 조건당 10쪽): 4px 배수 비율 42% → 90%

#### 파일럿 결과 (2026-10-16, 방법 시험)
- 과제 2개 × 조건 3개(도구 없음 / frontend-design / impeccable) × 2회 = 12쪽, 모델은 무료 gpt-oss-120b로 고정
- 설명서를 지시문으로 준 것이며 실제 Claude Code 플러그인 실행이 아님. 표본이 작아 **방법이 되는지** 확인한 것이지 도구의 우열 증거가 아님
- 자세한 수치: [design-pilot-result.md](design-pilot-result.md)

### 3-4. 한계를 숨기지 않는다
- 과제 3개, 사람 2명이라 **표본이 작다**. "이 조건에서 이랬다"까지만 말한다.
- 모델이 바뀌면 결과가 달라질 수 있어서 **날짜와 모델을 항상 표시**한다.
- 직접 확인은 **핵심 2~3개 조합**으로 시작한다(같은 시작 상태, 모델 버전, 과제별 성공 기준을 고정). 나머지는 "AI 추정" 또는 "제작자 주장"이다.

## 4. 제안서 6쪽에 쓸 실제 사례 (내 PC 실측, 2026-10-16)

| 도구 | 훅 | 시점별 개수 | 상시 토큰: 추정 → **실측** |
|---|---|---|---|
| superpowers 6.2.0 | 1 | 세션 시작 1 | 약 717 → **+1,377** |
| impeccable 4.0.4 | 2 | 도구 사용 후 1, 응답 종료 1 | 약 302 → 미측정 |
| ECC 2.2.0 | 22 | 도구 사용 전 8, 응답 종료 7, 세션 시작 2, 도구 사용 후 2, 압축 전 1, 도구 실패 후 1, 세션 종료 1 | 약 26,069 → **+8,198** |

- 훅 개수는 `hooks.json` 정적 집계다. 2026-10-17 실제 실행 기록으로 **세션 시작 2개·응답 종료 7개(ECC)** 와 세션 시작 1개(superpowers)가 매 세션 실행되는 것을 확인했다. 도구 사용 전 훅은 도구 종류에 맞는 것만 실행되므로 호출마다 실행 개수가 다르다.
- 실측 = Claude Code를 도구 조합별로 따로 실행해, 첫 응답에서 빈 환경보다 더 읽힌 입력 토큰(2회 재현, ±2). 글자수÷3 추정은 ECC에서 실측의 약 3배로 나와서, **토큰은 실측값을 우선**한다.
- ECC 개수(스킬 287·에이전트 68)는 설치된 2.2.0 기준이며, 최신 2.2.3 README는 311·71이다. 버전과 확인일을 같이 표시해야 하는 이유.

- superpowers + ECC: **세션 시작** 시점에 둘 다 훅이 실행됨(1개 + 2개). 함께 켜면 첫 응답 입력 토큰이 빈 환경보다 **+9,238**(실측). 같은 시점의 훅은 하는 일이 달라서 이것만으로 충돌이라 하지 않는다.
- impeccable + ECC: **도구 사용 후**와 **응답 종료** 시점에 둘 다 훅이 실행됨.
- 현재 내 환경에서는 ECC가 꺼져 있어서, 켜 둔 도구끼리는 겹침이 없다. 위는 "ECC를 켰을 경우" 계산이다.

슬라이드에는 도구 A·B·C 대신 이 이름과 숫자를 쓴다. 아직 **AI 의견은 비어 있다**(우리가 만들 부분).
