# 시험 3: 상황별로 기획 도구가 더 나은 기획을 해 주나? (2026-11-08)

## 무엇이 궁금했나요
추천은 "토큰이 적은 도구"가 아니라 **"내 상황에서 더 좋은 결과를 내는 도구"**여야 해요.
그래서 기획 분야에서 도구마다 **상황에 맞는 기획을 해 주는지**를 처음으로 직접 비교했어요.

## 무엇을 했나요
1. **실제 사용 상황 조사** (`조사_실사용상황.md`)
   - 사람들이 이 도구들을 어떤 상황에서 쓰는지 사용자 글과 비교 글을 읽고 상황을 골랐어요.
   - 상황 4개: 작은 수정 / 큰 새 프로젝트 / 목적이 흐릿한 새 아이디어 / 기존 코드에 기능 추가
2. **조건 4개로 같은 요청을 실행**
   - 도구 없음
   - Claude 기본 계획 모드
   - superpowers
   - gstack
   - 상황 4 × 조건 4 = 16번, 모델 sonnet, 각 1번
3. **답변지:** 첫 답이 질문으로 끝나면 미리 정한 답변지로 한 번 더 대답했어요 (예: "팀 3명, 6주, Spring Boot + MySQL + React").
4. **평가:** `평가표.md`의 상황별 항목(예/아니요)으로 Claude가 1차 표시했어요. **노형원 확인 전**이에요.

## 결과는 이랬어요

### 1. 상황에 맞는 기획인지는 네 조건 모두 거의 같았어요
평가표 항목을 네 조건 모두 거의 다 통과했어요.
- **작은 수정:** 모두 짧게, 기존 함수와 테스트를 지키는 계획을 냈어요.
- **큰 프로젝트:** 모두 단계, 범위, 위험, 테스트를 넣었어요.
- **흐릿한 목적:** 모두 먼저 묻거나 선택지를 냈어요.
- **기존 코드:** 모두 기존 저장 형식과 옛 데이터 호환을 챙겼어요.

→ **이번 4가지 상황에서는 도구를 켜도 기획 품질이 눈에 띄게 좋아지지 않았어요.** 기본 Claude가 이미 상황에 맞게 기획했어요.

### 2. 차이는 품질이 아니라 "일하는 방식"에서 났어요

| 조건 | 관찰한 방식 | 토큰 (4상황 합계, 입력 / 출력) | 시간 |
|---|---|---|---|
| 도구 없음 | 가정을 밝히고 바로 전체 계획 + 마지막에 질문 | 35만 / 1.8만 | 170초 |
| 계획 모드 | 계획을 파일(`~/.claude/plans/`)로 저장하고 대화에는 요약만 보여 줌 | 66만 / 2.1만 | 192초 |
| superpowers | 4번 모두 브레인스토밍 기능을 부름. 작은 수정에서는 질문 없이 바로 계획. 나머지 3개는 **"왜 필요한지" 질문 하나만 먼저** 하고 답을 받은 뒤 계획 | 57만 / **1.3만** (출력 가장 적음) | 142초 |
| gstack | **4번 모두 gstack 기능을 한 번도 쓰지 않음.** 결과가 도구 없음과 거의 같음 | 59만 / 1.9만 | 182초 |

- **superpowers:** 목적이 흐릿한 상황(③)에서는 질문부터 하는 방식이 잘 맞았어요. 다만 이미 할 일이 분명한 기존 코드 기능 추가(④)에서는 코드를 읽기 전에 "언제 태그가 필요했나요?"를 먼저 물어 한 번 더 주고받았어요.
  - 사용자 후기의 "이미 정한 걸 또 묻는다"와 비슷한 장면이에요.
- **gstack:** 자연어로 "계획 세워 줘"라고 하면 저절로 쓰이지 않았어요. `/office-hours` 같은 명령을 **직접 불러야** 효과가 있는 도구로 보여요.
  - 설치만 해서는 설명만 읽히고(처음 읽는 양 +1,135) 쓰이지 않는 셈이에요.
- **입력 토큰:** 질문을 한 번 더 주고받은 조건이 많아서, 입력 토큰은 대화 횟수 차이가 크게 반영됐어요. 도구 자체의 비용으로 읽으면 안 돼요.

### 3. 추천에 쓸 수 있는 문장 (초안, 시험 확인)
- **기획(일반):** "작은 수정·큰 프로젝트·기존 코드 기능 추가 기획은 기본 Claude(또는 계획 모드)로 충분했어요."
- **superpowers:** "무엇을 만들지 아직 흐릿할 때, 계획 전에 질문으로 생각을 정리하고 싶다면."
- **gstack:** "설치만으로는 쓰이지 않았어요. `/office-hours` 같은 명령을 직접 부를 사람에게." (명령 직접 호출은 아직 시험 안 함)

## 주의할 점 (꼭 같이 전달)
- **상황마다 1번씩**만 돌렸어요. 우연일 수 있어서 반복이 필요해요.
- **평가표가 너무 쉬웠어요.** 모두 통과해서 차이를 가려내지 못했어요. 더 어려운 항목이나 블라인드 비교(어느 도구 결과인지 가리고 사람이 고르기)가 필요해요.
- **시험 환경 오염:** 시험 PC의 전역 사용자 지침(`~/.claude/CLAUDE.md`)이 네 조건 모두에 읽혔어요(답변에 "NotebookLM은 쓰지 않았어요" 같은 문장이 나옴). 조건끼리는 같지만, 일반 사용자 환경과는 달라요. 깨끗한 환경에서 다시 돌려야 해요.
- **계획 모드:** 자동 실행이라 계획 승인 도구를 쓰지 못했어요. 그리고 계획 파일을 시험 폴더 밖(`~/.claude/plans/`)에 4개 만들었어요.
- **gstack 설치 방식:** 측정 때처럼 스킬 폴더를 시험 폴더에 복사하는 방식으로 켰어요(공식 setup 스크립트와 다를 수 있음).
- **도구 권한:** 안전을 위해 명령 실행(Bash)과 인터넷을 막고 돌렸어요. 이 권한이 필요한 기능은 시험되지 않았어요.
- **범위:** GSD, planning-with-files(여러 세션에 걸친 긴 작업), pm-skills(PRD)는 이번 범위가 아니에요.
