## 읽는 법
1. **기획 품질은 도구 없이도 만점이에요.** 3번 반복해도 같았어요.
   - 도구 없음이 네 상황 모두 만점이고, 토큰은 가장 적거나 거의 가장 적어요.
   - 기획 분야는 "기본 기능으로 충분"의 시험 근거가 생겼어요.
2. **superpowers**
   - 큰 프로젝트·흐릿한 목적에서는 질문 하나를 먼저 하고 짧은 계획을 내요. 출력이 도구 없음의 절반 정도이고 가장 빨라요.
   - 기존 코드 기능 추가에서는 3번 모두 코드를 보기 전에 "왜 필요하세요?"를 먼저 물었어요(감점 항목).
   - 작은 수정 1번은 계획을 별도 파일로 남겼어요.
3. **gstack 자연어:** gstack 기능을 쓰지 않아 도구 없음과 결과가 같아요.
   - 작은 수정·기존 코드 일부 감점(S1 r1, S4 r3)은 **우리 설치 방식 탓**으로 보여요.
   - gstack 파일 수백 개를 시험 폴더 안에 복사해서, Claude가 "앱 코드는 없고 gstack 폴더만 있다"고 착각했어요. 실제로는 사용자 폴더(`~/.claude/skills`)에 설치하니 이 감점은 결론에서 빼요.
4. **gstack 명령 직접 호출**
   - **`/office-hours`(큰 프로젝트·흐릿한 목적):** 다른 조건에 없는 것을 했어요. 큰 프로젝트 3번 모두 "실제로 쓸 사람이 있나(수요 검증)"를 따졌고, "가장 작게 시작할 범위"도 짚었어요. 다른 조건에서는 큰 프로젝트의 수요 검증이 0번이었어요. 대신 토큰이 도구 없음의 6~9배예요.
   - **`/plan-eng-review`(코드 수정):** "무엇을 검토할까요?"라고 되물었어요. 새 계획을 세우는 명령이 아니라 **이미 있는 계획이나 변경을 검토하는 명령**이에요. 감점은 명령을 잘못 고른 우리 쪽 문제에 가까워요.
5. **계획 모드:** 항상 만점이고 계획을 파일로 남겨요. 토큰은 도구 없음의 약 2배예요.

## 추천 문장 초안 (시험 확인, 3번 반복)
- 작은 수정·기존 코드 기능 추가·큰 프로젝트 기획: **기본 Claude로 충분**
- superpowers: 무엇을 만들지 흐릿할 때 질문 하나로 정리하고 **짧고 빠른 계획**을 원하면. 이미 할 일이 분명한 기존 코드 작업에선 한 번 더 묻는 편
- gstack `/office-hours`: **"만들 가치가 있나"를 따져 보고 싶을 때**. 토큰이 많이 듦
- gstack 설치만: 명령을 부르지 않으면 차이 없음
