# 시험 4: 테스트·리뷰·보안 분야 (2026-11-14)

깨끗한 환경(시험 3 v3와 같음), 각 3번. 채점은 정해진 규칙(AI 채점 없음)이고, 애매한 경우 답을 직접 읽어 확인했다.

## 4-1. 보안 검사 (`code/run_sec_test.py`)
- **과제:** 작은 회원 관리 서버의 작업 브랜치에 보안 구멍 3개(SQL 주입, 명령 주입, 경로 조작)와 생김새가 비슷한 안전한 코드 1개를 넣었다.

| 조건 | 찾은 수 (3번) | 헛경보 | 토큰 | 시간 |
|---|---|---|---|---|
| 자연어 ("보안 문제 검토해 줘") | 3, 3, 3 | 0 | 7~10만 | 14~23초 |
| 기본 `/security-review` | 3, 3, 3 | 0 | **약 4만** | 17~18초 |
| claude-code-security-review (명령 파일 설치) | 3, 3, 3 | 0 | 약 4만 | 17~20초 |
| trailofbits (스킬 모음 + 자연어) | 3, 3, 3 | 0 | 9~14만 | 19~23초 |

- **모두 만점이었어요.** 차이는 토큰뿐이고, 기본 `/security-review`가 가장 적게 썼어요.
- **claude-code-security-review:** 기본 명령과 이름이 같고, 토큰·결과도 거의 같아요. 설치해도 달라지는 게 없었어요.
  - 어느 쪽 명령이 실제로 돌았는지는 기록으로 구분하지 못했어요. 내용이 같은 명령이라 그래요.
- **trailofbits:** 스킬 44개 묶음인데, 이 과제에서는 스킬을 한 번도 쓰지 않았고 토큰만 늘었어요.
- **채점 규칙 실수 1건:** trailofbits 1번에서 헛경보가 잡혔지만, 직접 읽어 보니 "search_by_email은 안전하다"고 비교로 든 것이었어요. 헛경보 0으로 바로잡았어요.

## 4-2. 브라우저 도구 (`code/run_browser_test.py`)
- **과제:** "추가 버튼을 눌러도 안 돼." 진짜 원인은 투명한 알림 층이 버튼을 덮고 있는 거예요.
- **처음 과제를 바꾼 이유:** 처음엔 코드를 같은 폴더에 줬더니 브라우저 없이 코드만 읽어서 풀렸어요(`results_browser/_v1_code_in_folder/`). 그래서 "코드 없이 배포된 사이트 주소만" 주는 실제 상황으로 바꿨어요.

| 조건 | 원인 맞힘 | 방식 | 시간 | 토큰 |
|---|---|---|---|---|
| 도구 없음 (명령도 막음) | 0/3 | 사이트를 볼 방법이 없어 "추측하지 않겠다"고 답함 | 13~24초 | 6~12만 |
| 기본 + 그 사이트만 `curl` 허용 | 3/3 | 페이지 코드를 받아 CSS를 읽고 **추론** | 12~15초 | 9~12만 |
| playwright-mcp | 3/3 | 실제로 클릭 → "toast-layer가 클릭을 가로챔" **확인** | 22~26초 | 15~19만 |
| chrome-devtools-mcp | 3/3 | 실제로 입력·클릭 → 버튼 위 요소를 **확인** | 20~24초 | 20~23만 |

- **브라우저 도구:** 둘 다 "실제로 눌러 보고 확인했다"는 근거를 대요.
- **`curl`로 받아 읽기:** 더 빠르고 싸지만, 원인을 코드로 추론할 뿐 실제로 눌러 보지는 않아요.
- **이번 버그는 CSS에 보이는 버그라** 코드를 읽어도 풀렸어요. 화면을 실행해야만 보이는 버그(실행 중에 생기는 상태 등)라면 차이가 더 클 거예요.
- **진행 중 실수:** `curl` 허용 규칙을 처음 두 번 잘못 써서 실행이 막혔어요(`_curl_rule_wrong`, `_curl_rule_wrong2`). 세 번째(`curl *127.0.0.1:포트*`)에 정상으로 돌았어요.

## 4-3. 코드 리뷰 (`code/run_review_test.py`)
- **과제:** 회비 함수 작업 브랜치에 로직 버그 3개를 넣었어요.
  - 빈 목록이면 0으로 나눔
  - 1부터 시작하는 페이지인데 한 칸 밀림
  - 이메일이 아니라 이름으로 중복 판단

| 조건 | 찾은 수 | 토큰 | 시간 | 더 짚은 것 |
|---|---|---|---|---|
| 자연어 ("리뷰해 줘") | 3, 3, 3 | 약 7만 | 약 12초 | 이메일 대소문자 문제 등 |
| 기본 `/code-review` | 3, 3, 3 | 11~15만 | 약 17초 | 이메일 대소문자, 테스트 없음, 중복 코드 (답은 영어) |

- **둘 다 만점이었어요.** 기본 `/code-review`는 테스트와 코드 중복까지 짚지만 토큰이 더 들고, 답을 영어로 했어요.
- **채점 규칙 실수 1건:** 처음 규칙이 한국어 위주라 영어 답을 놓쳐 1~2개로 나왔어요. 답을 직접 읽고 규칙을 고쳤어요.

## 이번엔 못 한 것
- **open-code-review:** 위임 모드도 별도 프로그램(`ocr`, npm 패키지) 설치가 필요해요. 내려받기 허락이 필요해서 보류했어요.
- **tdd-guard:** 별도 프로그램과 pytest 연결 장치가 필요해서 보류했어요.

## 추천 문장 초안 (시험 확인)
- **보안 검사:** 기본 `/security-review`로 충분해요. 가장 싸고, 심어 둔 구멍을 모두 찾았어요.
  - claude-code-security-review의 명령 파일은 설치해도 차이가 없었어요(GitHub 자동 검사 기능은 시험 안 함).
  - trailofbits는 이 과제에선 토큰만 늘었어요.
- **코드 리뷰:** 자연어 요청으로도 충분했어요. 기본 `/code-review`는 테스트·중복까지 넓게 보지만 더 비싸요.
- **브라우저 도구 (playwright-mcp, chrome-devtools-mcp):** 코드가 없는 사이트의 문제를 **실제로 눌러 보고 확인**하고 싶을 때. 코드가 있으면 기본 Claude가 읽어서 더 빠르게 찾아요.
