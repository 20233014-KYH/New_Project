# "새로운 프로젝트 시작"

> 오픈소스기반 기초설계 팀 프로젝트 저장소입니다. 지금은 **기획을 정리하는 단계**이고, 곧 각자 맡은 부분을 만들기 시작합니다.

## 한 줄 소개

내가 쓰는 Claude 도구를 담으면, **비슷한 일을 하는 도구가 겹쳐서 토큰이 낭비되는지** 알려 주고 **무엇을 더 쓰면 좋은지** 추천해 주는 **한국어 웹 서비스**입니다.
(프로젝트 이름은 아직 정하지 않았고, 지금은 "AI 도구 인벤토리"라는 가칭을 씁니다.)

## 왜 만들까요?

- Claude를 더 잘 쓰게 해 주는 도구(플러그인, 스킬, MCP 서버 등)는 많은데 설명이 **대부분 영어**이고 여기저기 흩어져 있습니다.
- 도구를 모아 둔 곳은 많지만 **내 상황에 맞는지는 알려 주지 않습니다.**
- 비슷한 일을 하는 도구를 여러 개 켜 두면 같은 일에 **토큰이 여러 번** 쓰이는데, 설치 전에는 알기 어렵습니다.
- Claude에 **이미 들어 있는 기능**을 모르고 같은 일을 하는 오픈소스를 또 설치하기도 합니다.

## 이렇게 쓰게 됩니다 (예시)

1. 사용자가 사이트에서 지금 쓰는 도구를 **도구함**에 담습니다. (내 컴퓨터를 읽어 가지 않고, 직접 고릅니다.)
2. 써볼 도구를 하나 더 담습니다. 예를 들어 `superpowers`를 쓰는 중이고 `ECC`를 써볼 예정이라면:
   > ⚠ 겹침 가능성: 둘 다 일하는 순서를 정하는 도구예요. 같이 켜면 비슷한 일에 토큰이 두 번 쓰일 수 있어요. 하나만 쓰는 것을 권장해요.
3. 결과에는 **확인일**과 **사실인지 AI 추정인지**가 함께 표시됩니다.

## 기획 한눈에 보기

| 정한 것 | 내용 |
|---|---|
| 메인 기능 | AI 판정: 같이 써도 되나(겹침·보완·용도별), 토큰은 어떻게 되나, 이 도구는 어디까지 하는 도구인가 |
| 서브 기능 | 분야별 도구 소개 (한국어). 분야 6개: 기획·작업 방식 / 토큰·컨텍스트 / 코드 이해·검색 / 디자인·프론트엔드 / 백엔드·인프라 / QA·테스트 |
| **충돌의 뜻** | 비슷한 일을 하는 도구를 동시에 켜서 토큰이 낭비되는 것(겹침). 실제로 오작동하는 경우는 재현 기록이 있을 때만 따로 표시 |
| **안전·위험 판정은 하지 않음** | 대신 "이 도구가 어디까지 할 수 있는지"(훅·구성 요소 등)를 사실로 보여 줍니다 |
| 판정 방식 | **미리 판정해 저장**하고, 저장되지 않은 조합일 때만 API로 판정 |
| 믿을 수 있게 | 확인일·도구 버전 표시, 업데이트되면 표시, **사실 / 제작자 주장 / AI 추정 / 직접 확인**을 구분 |
| 새 도구 | 새로 나온 도구를 자동으로 찾아 후보로 올리고, **사람이 확인한 뒤** 추가 (3단계) |
| 기술 | React + Tailwind (화면), Spring (서버), 데이터는 JSON으로 시작 |
| 시작 규모 | 분야마다 4개 이상, 6개 × 6분야 = 36개로 시작해서 늘림 |
| 범위 | Claude Code 우선 |

## 프로젝트는 이렇게 진행해요

> 자세한 내용은 [docs/team-workflow.md](docs/team-workflow.md)에 있습니다. 아래는 요약입니다.

1. **각자 자기 성(영문 대문자)으로 브랜치를 만듭니다.** 예: 노 → `ROH`, 김 → `KIM`
2. **내 브랜치에서만 작업**하고, `main`에는 직접 올리지 않습니다.
3. 작업이 한 덩어리 끝나면 **Pull Request(PR)** 로 `main`에 올립니다. 제목은 `[ROH] 한 줄 설명`.
4. **다른 팀원 1명 이상이 확인(리뷰)** 한 뒤에 합칩니다.
5. 각자 **맡은 폴더만** 수정합니다. 다른 사람 폴더나 `docs/`를 바꾸고 싶으면 PR 코멘트나 이슈로 요청합니다.
6. **API 키·비밀번호는 절대 올리지 않습니다.**
