# "새로운 프로젝트 시작"

> 오픈소스기반 기초설계 팀 프로젝트 · 지금은 **기획을 정리하는 단계**예요 (코드는 아직 없어요)

## 이게 뭐예요?

**내가 쓰는 Claude 도구를 고르면, 겹치는 도구를 알려 주고 뭘 더 쓰면 좋을지 추천해 주는 한국어 웹사이트**예요.
(이름은 아직 없고, 임시로 "AI 도구 인벤토리"라고 불러요.)

예를 들어 이렇게 알려 줘요.

> `superpowers`를 쓰는 중인데 `ECC`를 추가하려고 하면
> ⚠ **둘 다 "일하는 순서"를 정하는 도구예요. 같이 켜면 같은 일에 토큰(Claude가 읽는 글자 양)이 두 번 쓰여요. 하나만 쓰는 걸 권해요.**

## 팀원이 지금 할 일 (3가지)

**① 내 브랜치 만들기** (이름은 내 성을 영문 대문자로: 노 → `ROH`, 김 → `KIM`)
```bash
git clone https://github.com/20233014-KYH/New_Project.git
cd New_Project
git switch -c 내성        # 예: git switch -c KIM
git push -u origin 내성
```

**② 기획안 읽고 모르는 곳에 코멘트 남기기**
→ [docs/proposal-ROH.md](docs/proposal-ROH.md)
**1장(요약) · 5장(카테고리) · 9장(정할 것)** 만 읽어도 돼요. 이해가 안 되거나 반대하는 곳은 그 줄에 코멘트를 달아 주세요.

**③ 9장의 "남은 결정"에 의견 적기**
프로젝트 이름 · 처음 넣을 도구 36개 · 누가 무엇을 맡을지 · 일정

## 앞으로 이렇게 일해요

1. **내 브랜치에서만** 작업해요. `main`에는 직접 올리지 않아요.
2. **내가 맡은 폴더만** 고쳐요.
3. 한 덩어리가 끝나면 **PR**로 올려요. 제목은 `[성] 한 줄 설명`.
4. **팀원 1명 이상이 확인**한 뒤에 합쳐요.
5. **API 키·비밀번호는 절대 올리지 않아요.**

→ 자세한 방법: [docs/team-workflow.md](docs/team-workflow.md)

<details>
<summary><b>왜 만들까요?</b></summary>

- Claude를 잘 쓰게 해 주는 도구는 많은데 설명이 **대부분 영어**이고 흩어져 있어요.
- 도구를 모아 둔 곳은 많지만 **내 상황에 맞는지는 알려 주지 않아요.**
- 비슷한 도구를 여러 개 켜 두면 **같은 일에 토큰이 여러 번** 쓰이는데, 설치 전에는 알기 어려워요.
- Claude에 **이미 들어 있는 기능**을 모르고 같은 일을 하는 도구를 또 설치하기도 해요.

</details>
