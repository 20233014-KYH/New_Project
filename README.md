# "새로운 프로젝트 시작"

> 오픈소스기반 기초설계 1조 팀 프로젝트 · **지금 단계: 기획 확정 → 만들기 준비 중**

## 무엇을 만드나요?

**Claude Code에 설치하는 도구(플러그인·스킬·MCP)를 고르면, 겹쳐서 손해 보는 조합을 알려 주는 한국어 웹사이트**예요.
이름은 아직 없어서 임시로 "AI 도구 인벤토리"라고 불러요.

예를 들면 이런 걸 알려 줘요.

> **superpowers를 쓰는 중에 ECC를 더하면?**
> 둘 다 "개발을 진행하는 순서"를 정하는 도구예요. 같은 과제를 시켜 보니 결과는 똑같았지만 토큰(Claude가 읽는 글자 양)은 약 1.9배 들었어요. (시험 기록은 `judgment/experiments/`에 올려요)

## 처음 왔다면 (3단계)

1. 이 README를 끝까지 읽어요 (2분).
2. [docs/team-workflow.md](docs/team-workflow.md)를 보고 **내 성으로 브랜치를 만들어요** (노 → `ROH`, 김 → `KIM`).
3. 내가 맡은 폴더(아래 표)에서 일하고, 끝나면 **PR**로 올려요.

## 폴더 구조

| 폴더 | 무엇을 두나요 | 담당 |
|---|---|---|
| `docs/` | 기획안, 판정 기준, 일하는 방법 | 다 같이 (고칠 때는 PR 리뷰) |
| `data/` | 도구 목록과 도구 정보 | ① 수집 담당 |
| `judgment/` | 겹침 판정 기준, 판정 결과, 시험 기록 | ② 판정 담당 |
| `web/` | 화면 (React + Tailwind) | ③ 웹 담당 |
| `server/` | 서버 (Spring) | ③ 서버 담당 |
| `prototype/` | 미리 해 본 실험 코드 | 누구나 |

담당자 이름은 정해지면 이 표에 적어요.

## 일하는 방법 (꼭 지킬 5가지)

1. `main`에 바로 올리지 않아요. **내 브랜치 → PR → 팀원 1명 확인 → 합치기.**
2. **PR 하나에는 주제 하나만** 담아요.
3. **내 폴더만** 고쳐요. 다른 폴더는 PR 코멘트나 이슈로 요청해요.
4. **API 키·비밀번호는 절대 올리지 않아요.**
5. 확인 안 한 내용은 사실처럼 쓰지 않고 **"확인 안 됨"**이라고 써요.
