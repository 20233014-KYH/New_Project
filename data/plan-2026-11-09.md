# 이번 주 할 일: 36개 도구 조사 (2026-11-09 ~ 11-13)

담당: 허준서

## 목표

36개 도구를 **기능, 특징, 비용, 보안성** 네 가지 기준으로 조사합니다. 앞에서 조사한 12개(카테고리별 앞 2개)도 같은 기준으로 다시 정리합니다.

나중에 추천 기능을 만들 때 근거가 될 자료를 갖추는 것이 목적입니다. 이번 주 범위는 **같은 카테고리 안에서 각 도구가 어떤 장점이 있는지 찾는 데까지**이고, 그 장점으로 실제 추천을 계산하는 것은 다음 단계입니다.

## 기준별 조사 방법

### 1. 기능
- 각 도구의 README와 공식 문서를 기준으로, 무엇을 하는 도구인지 한두 문장으로 쓰고 주요 기능을 서너 개 정리합니다.
- 원문에서 확인한 내용만 씁니다. 확인 못 한 값은 "확인 안 됨"으로 둡니다.

### 2. 특징 (이번에 새로 추가)
- 같은 카테고리의 6개를 나란히 놓고 **작동 방식, 작동 위치, 준비물, 규모**를 비교합니다.
- 도구마다 "이 도구에만 있는 점"과 "이런 상황이면 이 도구"를 찾습니다.
  - 예: caveman과 rtk는 둘 다 토큰을 줄이지만, caveman은 Claude가 **쓰는 답변**을, rtk는 Claude가 **읽는 명령 결과**를 줄입니다.
- 원문에 있는 사실(`doc`)과, 그 사실을 보고 우리가 정리한 비교(`ai`)는 구분해서 표시합니다.

### 3. 비용
- **라이선스**: 무료로 쓸 수 있는지
- **추가 비용**: 유료 API 키나 외부 서비스 계정이 필요한지
  - 예: claude-context는 임베딩·벡터 DB, supabase나 Figma 관련 도구는 해당 서비스 계정이 필요
- **토큰 비용**: 팀이 실측한 "도구 없이 쓸 때보다 늘어난 토큰" 값을 그대로 씁니다
  ([judgment/review/2026-10-18-measure36/measured_36.csv](../judgment/review/2026-10-18-measure36/measured_36.csv)). 훅·MCP의 실제 비용은 포함되지 않는다는 점을 함께 적습니다.

### 4. 보안성
- 지난주에 만든 스캐너(`security/scanner/`, PR #12)를 나머지 24개에도 돌려서 36개 전체를 **접근 범위 표**로 만듭니다.
- 칸은 6개: 내 파일 / 설정 바꾸기 / 명령 실행 / 밖으로 보내기 / DB·외부 서비스 / 브라우저
- 사실만 적고, "안전하다/위험하다"를 단정하지 않습니다. "찾지 못함"은 "없음"이 아닙니다.
